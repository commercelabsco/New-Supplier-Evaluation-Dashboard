Changelog — Google Sheet Sync

2026-09-24

Summary

The dashboard needed one shared place to store evaluations so people working from different locations all see the same data. A Google Sheet backend was set up for this earlier, but it wasn't actually reachable for anyone outside the deploying account, so evaluations silently stopped syncing. This pass removed the leftover dead code that made the failure invisible, and rebuilt the Sheet integration correctly, with the likely cause of the original break called out explicitly so it isn't repeated on redeploy.

Before

The app is one static index.html with no server of its own. Earlier commits had already wired it to a Google Sheet through a small Apps Script Web App (google-apps-script/Code.gs), reachable at a hardcoded SHEET_WEBAPP_URL. It looked done, but the deployment URL was shaped:

https://script.google.com/a/macros/commercelabs.co/s/.../exec

— a domain-restricted Apps Script deployment.

What was done

  1. Removed the Sheet integration temporarily (f3d72e1) — reverted index.html's storage layer to window.storage with an in-memory fallback, and deleted google-apps-script/, so the app wasn't silently failing for anyone while a proper fix was worked out.
  2. Rebuilt the Sheet integration properly (27fee65):
    • Restored google-apps-script/Code.gs and README.md.
    • Removed window.storage from index.html entirely — it only ever works inside Claude's own artifact preview, never in a real browser / GitHub Pages deployment, so it could never have served two real users anyway.
    • Sheet response parsing now detects an HTML page coming back (instead of JSON) and raises a clear error naming the domain restriction as the likely cause, instead of a bare "JSON parse failed".
    • Code.gs now wraps every read/write in a LockService lock so two people saving at the same instant from different locations can't race each other into a corrupted or duplicate row.
    • README.md spells out, step by step, that the Apps Script must be deployed with "Who has access: Anyone", not the Workspace-domain-restricted option, and how to fix an existing deployment that has it wrong.
    • SHEET_WEBAPP_URL is left as a placeholder pending a fresh deployment URL.

Why it broke the first time

Google's Web App deploy dialog can quietly default to "Anyone within [Workspace domain]" instead of "Anyone" when the deploying Google account belongs to an organization (e.g. a company account). A domain-restricted deployment only serves JSON to visitors currently signed into a Google account on that same domain, in that same browser. Every other visitor — a different browser, a different device, someone not signed into a company Google account — gets redirected to an HTML sign-in page instead of data. The dashboard's old code treated that as "unreachable" and silently dropped into session-only memory mode, with no error shown, which is exactly why it looked like it worked for one person and not for anyone else.

Separately, window.storage (the fallback/primary storage used before this) is a Claude-artifact-preview-only API. It was never going to give two real users shared data even when it "worked" — it isn't a real browser API, and different users/devices each get their own isolated instance. It has now been removed entirely so it can't mask a Sheet failure again.

Benefit

Once the Apps Script is deployed with Anyone access and the resulting URL is pasted into SHEET_WEBAPP_URL, every evaluator — regardless of device, browser, or physical location — reads and writes the same Google Sheet. Two people can work at the same time without overwriting or losing each other's data (the new lock prevents write races), and a clear on-screen error now shows up immediately if the deployment is ever misconfigured again, instead of quietly falling back to a private, unsynced session.

Next step (needs you)

  1. Open the target Google Sheet → Extensions → Apps Script.
  2. Deploy → Manage deployments (or New deployment) → edit → set "Who has access" to Anyone → Deploy.
  3. Copy the resulting URL (should look like https://script.google.com/macros/s/AKfycb.../exec, not containing /a/macros/<domain>/).
  4. Paste it into SHEET_WEBAPP_URL near the top of index.html's <script> block.
  5. Test from a private/incognito window (or a different device) to confirm evaluations sync both ways.

Full setup steps are in google-apps-script/README.md.
